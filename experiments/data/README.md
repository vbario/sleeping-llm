# experiments/data — EGO-SELECT pre-registration artifacts

Spec: `notes/131-ego-selector-experiment` (v2). This directory holds the frozen
inputs of the EGO-SELECT matrix. **Freeze-order discipline (§7.4)** — git
history is the proof of order, so these files must be committed in this
sequence and never edited afterwards:

1. `notes/131-ego-selector-experiment` — the plan itself.
2. **`borrowed_rules.yaml` + `ego_prompts.yaml`** (this directory) — the C2
   rule table, the C4/C5 charter seed, the C3 filler, the C3b rules-prose
   block, both counterfactual instructions, the shared listing/output format,
   and the C5 self-model update prompt. These are authored **blind to the
   corpus**: the corpus does not exist yet when they are committed, and the
   keyword-leak check later asserts zero content-word overlap between the
   charter and any fact's value tokens (§5 blindness controls).
3. `ego_corpus_v1.json` — generated by `experiments/make_ego_corpus.py`,
   committed only after it passes the decorrelation check, the keyword-leak
   check, and the cell-G rule-score constraints. The corpus generator MAY read
   the committed rules (needed to construct coverage gaps); the rules can
   never see the corpus.
4. `ego_corpus_stream.json` + oracle-simulation output + derived G3 threshold —
   emitted by the freeze phase (§7.1), committed before the matrix runs.

Direction of information flow is one-way: rules/prompts → corpus → stream →
matrix. Any change to an earlier artifact invalidates and forces regeneration
and recommit of everything after it — and, for files at step 2, invalidates
the blindness claim entirely (they may not be revised once the corpus exists).

Token-matching note: `filler_generic` and `rules_prose` in `ego_prompts.yaml`
are matched to `charter_seed` within ±5% by whitespace-token count (counts
recorded as comments in that file) so C3/C3b/C4 differ only in content, not
prompt length (§4, risk F4).
